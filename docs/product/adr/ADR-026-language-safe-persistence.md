## Context

Every user-owned store is **keyed by ids**. Stored *text* exists in four places:

| Store | Stored text | Unknown fields on re-save |
|---|---|---|
| Journal `circle_journal_v1` | `session.title` (generated "Your Circle", or the kept name), `session.replacedFromTitle`, legacy `pathName` | **Dropped:** `CircleJournalEntry.toJson` (`circle_journal.dart:456`), `CircleSessionRecord.toJson` (`:194`) |
| Kept Circles `toolkit_v1` | `name` (typed, or generated by `keptCircleDefaultName`, `kept_circles_provider.dart:494`); `wording[]` per part (`:382`) | **Preserved** (`KeptCircle.stored`, `kept_circle.dart:50`, `:74`) |
| Insights `insights_v2` | `InsightSnapshot.text` "exactly as shown" (`insight.dart:243`); `NothingToChange.text` (`:203`) | **Preserved** (`InsightSnapshot.source`, `:233`) |
| Settings | `user_first_name_v1` (typed) | n/a |

Plans and suggestion preferences hold no display text.

**Today's integrity protections, all preserved by this ADR:**
- the journal forward-record rule: an entry from a newer schema is kept as stored, never rewritten (`circle_journal.dart:507`);
- whole-journal preservation (R6c);
- `RetainedKept` and damaged-wording handling (R4/R8 A07, `kept_circle.dart:125`);
- unknown-field preservation in kept Circles, Plans, Insights and suggestion preferences;
- the L-1 unreadable-preferences path;
- Delete intent-first and confirmed steps (R8);
- confirmed writes;
- the R6 whole-Circle voice rule (`composed_session.dart:191, :199`).

## Part A — Principles (for approval under D-L-5a/b; **no journal migration, no new field in any persisted or exported record**)

### A-1. Ids are identity

No displayed, translated or branded text is ever a lookup, ownership, history or origin key. Existing id-based identities are unchanged:
- `circleId`, `activityId`, `ElementId`;
- kept `id`;
- `planId`/`cycleId`;
- Insight `id`/`subject`/`evidenceFingerprint` (which already excludes the wording, `insight.dart:65`);
- `ThirtyVoice.id`.

### A-2. Stored text is shown as saved

- Journal titles, kept names, kept wording snapshots, Insight text and the first name are displayed **verbatim**, in every UI language.
- They are never translated, rewritten, re-rendered or migrated (D-L-5a: no re-rendering in T2).
- Labels derived from ids may appear in the current UI language **beside** stored text, visibly separate:
  - need, activity, the parts line (`CirclePlan.fromWire(...).line`), answers, dates;
  - Plan and stage copy.
- A record without a known source language carries **no language label**. Nothing is guessed.
- **Display-only transforms** over stored text stay display-only and become locale-aware. Example: `InsightCopy.keepDatesTogether`, `insight_copy.dart:213`, which today rewrites English month names for display. They never write back.

### A-3. Language handling in memory and in the domain; no persisted metadata *(rev 2)*

**A-3a. Runtime (domain) language handling, not persisted:**
- The content locale of a running Circle is computed at runtime:
  - a composed Circle: the UI locale at Start (ADR-025 §7.4);
  - a kept Circle: its **established** content locale (A-3b).
- Spoken scripts, manifests and completeness are computed per locale in memory (ADR-025 §7.1–7.3).
- None of this adds a field to any user-owned or exported record.

**A-3b. How a kept Circle's content locale is established without new persisted metadata:**
- A kept-Circle record with **no** `sourceLocale` is English content.
- This is a **build-history invariant, not an inference**:
  - every build that can write such a record (all builds up to `b62984bc`, and every build whose release-locale set is `{en}`) can only write English wording;
  - saved wording is **never inspected** to decide or guess a language.
- **The invariant stays true only while kept Circles can be written in English alone. Hence the hard gate G-5C:**

> **G-5C.** No build whose release-locale set contains a non-English locale may run against a real (non-test) store, or be distributed, until D-L-5c is decided and, if approved, the persisted `sourceLocale` (B-0) is implemented.

  - Unit and widget tests with in-memory stores are exempt.
  - **Where it is enforced** (as implemented by L-INF; founder instruction 2026-11-12 that the app never refuses to launch):
    - the release-locale set is a compile-time constant, English only (`lib/core/l10n/thirty_locales.dart`), with no define, setting or language control that can widen it;
    - every device locale resolves to English and the app starts normally;
    - a guard test pins the constant, so widening it requires changing that test together with B-0.

**A-3c. If D-L-5c is refused:**
- B-0 is not implemented, and G-5C blocks every non-English release set.
- The founder then has to decide a different language-identity design. Inferring the language from wording is **not** an option.
- **Not** permitted as a substitute: a side store of per-Circle language outside the exported record. That would be user-record data left out of Export, against the Delete/Export contract.

### A-4. A language switch writes nothing

- A locale change never writes, regenerates, re-snapshots, migrates or re-saves any user-owned store.
- In particular, an Insight already shown is never regenerated in the new language, and Insight generation is never triggered by a locale change.
- **The only writes:** `app_locale_v1` (a confirmed write) and the reminder re-arm (native title and body).
- **Test:** six consecutive switches → identical bytes for every user-owned key, and a byte-identical Copy as text.

### A-5. Audio integrity: the saved-wording equality check (mandatory)

1. A Circle is voiced only when its content locale has a complete, approved rendition for the chosen persona **and every part's words equal that locale's recorded script for that element**. This is the R6 whole-Circle rule, unchanged.
   - The content locale is the one established under A-3b: English for every record without `sourceLocale`; the persisted `sourceLocale` only after B-0.
   - A single differing part → the whole Circle runs on screen and paced, with the R6 note.
   - **Legacy or unverified records** (no established locale, damaged or unverified wording, `RetainedKept`) are **never voiced** unless the byte-exact match against the recordings of their established language succeeds. There is never a mismatched or other-language clip.
2. **This equality is an audio-integrity check and nothing else.**
   - It may only **withhold** voice.
   - It never identifies a record, assigns ownership, infers origin or language, selects a translation or changes a stored byte.
   - It is the **only** text comparison permitted over stored user text.
3. **No cross-language substitution.** Words in locale X are matched only against locale-X recordings. If they don't match, the Circle is unvoiced; it never plays a recording in another language.
4. **Safety corrections** (`partWordingFor`, `circle_elements.dart:1045`) substitute the element's current words **in the snapshot's content locale**. A safety revision is global per element and invalidates every locale's clip by fingerprint.
5. **The English identity is frozen:**
   - the 180 English files keep their exact paths and FNV-1a script fingerprints;
   - legacy English snapshots are compared byte-exactly with them;
   - D-A (a) or (b) is decided under D-V-3.

### A-6. A running Circle keeps one language

- The in-flight composed session (`recommendation_composed`; transient, never exported) stores its pinned content locale (ADR-025 §7.4).
- A restored in-flight session without it resolves to English if it is a kept Circle with legacy wording, else to the current UI locale.
- This is not a journal or export change.

### A-7. Unreadable, legacy and newer records

- Handled exactly as R8, R6c, R4/R8 A07 and L-1 handle them today, in every UI language. Only their surrounding chrome is localized.
- No new unreadable state is introduced.
- An unsupported `app_locale_v1` value is kept as stored and ignored for resolution.

### A-8. Export *(rev 2)*

- **Part A changes nothing that is exported:**
  - the envelope, key set and `schemaVersion` (`exportAsJson`, `circle_journal.dart:1140`; `schemaVersion` at `:1154`) are unchanged;
  - **no persisted record gains a field**.
- This matters because records are exported **as stored**: kept Circles through `keptCircles` (`:1166`, fed from `journal_data_controls.dart:126`) and Insights through `insights` (`:1169`, fed from `:136`).
- **Any new field in those records is therefore an export-format change** (B-0), even though the envelope `schemaVersion` would not move.
- `app_locale_v1` is not exported.

### A-9. Onboarding interaction

A language preference alone never counts as existing-user evidence (D-ON-3, founder decision 2026-11-12; recorded in the pre-release product gap register, §2 G-01).

## Part B — HELD (not authorized by D-L-5a/b)

| Held item | Why it is held | Decision needed | Proposed handling when decided |
|---|---|---|---|
| **B-0.** Persisted `sourceLocale` on **new** kept-Circle records (proposed explicit language identity) and, optionally, on new Insight snapshots | Kept Circles and Insights are exported as stored (A-8), so the field changes the exported JSON payload: an **export-format change** | **D-L-5c:** explicit export-format disposition by the founder (recommended in the same export revision as D-RL4 / B-1 / B-2, so the export changes once). **Must be decided before G-5C can lift** | `sourceLocale` written once at Keep, never rewritten. Older builds preserve it through `KeptCircle.stored` / `InsightSnapshot.source` (unknown-field preservation, unchanged). Records without it stay English under A-3b. Newer-schema and unreadable records keep the R8/R4 handling |
| **B-1.** Journal entry metadata (`sourceLocale` on the entry; `titleOrigin` on `session`) | Journal `toJson` drops unknown fields, so adding them at schema 2 would be silently stripped by any older build. The code's own rule (`circle_journal.dart:645–653`) requires a reviewed schema bump. A bump also changes the exported `schemaVersion` | D-RL4 + export-format decision | Journal **schema 3**, readable `{1,2,3}`; older builds keep v3 entries as stored (the R8 forward rule) |
| **B-2.** Export envelope fields (`exportVersion`, app locale) | An export-format change (mandate rule 8) | D-RL4 + export-format decision | The same revision as B-0/B-1 |
| **B-3.** Re-rendering generated stored text in another language | Not needed for T2 (A-2); needs origin metadata (B-1) | A separate future decision | — |

**Until Part B is decided:**
- the journal stays at schema 2;
- kept Circles stay at schema 1 **with no new field**;
- Insights are unchanged;
- History shows stored titles verbatim, with id-derived details in the UI language (A-2);
- **G-5C keeps every build English-only for persistence purposes.**

## Consequences

- No migration, no rollback risk and no export change under Part A.
- **L-INF, English extraction, the content-locale API and the guards** can all proceed under Part A alone, because the release set stays `{en}`.
- **Before the first build that can write non-English kept Circles** (any T1 language pilot on a real device included), D-L-5c must be decided.
- **History in a non-English UI** (after G-5C lifts) shows earlier generated titles in the language they were saved in. This is accepted under A-2.

## Acceptance

- AT-SW-1…5, AT-LEG-1…3, AT-FUT-1…4 and AT-FP-1…5 under Part A.
- **Rev 2 addition:** Copy as text is byte-identical for every fixture store before and after each Part A step.
- **AT-FUT-5 and AT-AC-1/2 with non-English Circles** run only after B-0 (D-L-5c) and D-L-8.
